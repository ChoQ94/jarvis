# jarvis

텔레그램으로 알람과 알림을 받는 개인용 봇.

1. **리마인더** — 내가 정한 시각에 알람 (말하듯 등록)
2. **감시** — OpenRouter에 새 AI 모델이 올라오면 알림

서버를 24시간 띄워둘 필요 없이 **Cloudflare Workers 무료 플랜**에서 돌아갑니다.

배포 주소: `https://jarvis.choq.workers.dev`

---

## 구조

시스템은 **두 개의 독립된 흐름**으로 되어 있습니다. 이 둘은 서로를 직접 호출하지 않고,
오직 **D1 데이터베이스를 통해서만** 연결됩니다.

### 흐름 1 — 등록 (알람을 저장할 때)

입력 창구는 셋이지만, **해석과 저장은 한 곳으로 모입니다.**

```
 텔레그램 앱          웹 채팅 UI            터미널
 "내일 3시에 병원"    "내일 3시에 병원"      npm run cli -- add ...
      │                    │                     │
      ▼                    ▼                     │
 텔레그램 서버      비밀번호 로그인               │
      │             (쿠키 인증)                  │
      │ webhook            │                     │
      ▼                    ▼                     │
 ┌───────────────────────────────────┐           │
 │  Worker : fetch()                 │           │
 │  ─ 시크릿 헤더 / 쿠키 검증          │           │
 │  ─ chat_id 화이트리스트            │           │
 └────────────────┬──────────────────┘           │
                  ▼                              │
      ┌───────────────────────────┐              │
      │  자연어 해석 (nlp.ts)       │              │
      │                           │              │
      │  1단계 규칙 파서 ─── 성공 ──┼──┐           │
      │      │ 실패                │  │           │
      │      ▼                    │  │           │
      │  2단계 Workers AI          │  │           │
      └───────────────────────────┘  │           │
                                     ▼           ▼
        ┌────────────────────────────────────────────┐
        │           D1 (SQLite) — reminders          │
        │  id │ message │ cron │ once_at │ last_sent │
        └────────────────────────────────────────────┘
```

**대부분은 1단계에서 끝납니다.** 조사(`3시에`), 꼬리말(`알려줘~`), 요일 계산
(`다음주 월요일`)까지 규칙으로 처리하므로 0ms·무료입니다.
AI는 규칙이 실패한 문장에만 호출됩니다.

> 세 경로 모두 **같은 해석기와 같은 명령 처리기**를 씁니다.
> 어디서 등록하든 문법과 결과가 같고, 알림은 항상 텔레그램으로 갑니다.

### 흐름 2 — 발송 (알람이 울릴 때)

```
 ┌────────────────────────────┐
 │  Cloudflare Cron Trigger   │   "* * * * *"  (매 분)
 └─────────────┬──────────────┘
               │ Worker 를 깨움
               ▼
 ┌──────────────────────────────────────────────┐
 │  Worker : scheduled()                        │
 │                                              │
 │  1. SELECT * FROM reminders WHERE enabled=1  │◀──── D1
 │  2. UTC → Asia/Seoul 벽시계 시각 변환          │
 │  3. 크론식이 지금과 맞는가? / once_at 지났는가? │
 │  4. last_sent 와 같은 분이면 건너뜀 (중복 방지) │
 └─────────────┬────────────────────────────────┘
               │ 보낼 게 있으면
               ▼
      텔레그램 Bot API (sendMessage)
               │
               ▼
         📱 "⏰ 스탠드업"
               │
               ▼
      D1 에 last_sent 기록 ──▶ 같은 분에 두 번 울리지 않음
```

### 흐름 3 — 감시 (새 AI 모델이 올라왔을 때)

```
 ┌────────────────────────────┐
 │  Cron Trigger — 매시 정각   │
 └─────────────┬──────────────┘
               ▼
 ┌──────────────────────────────────────────────┐
 │  watchers/openrouter.ts                      │
 │                                              │
 │  1. openrouter.ai/api/v1/models 조회          │
 │  2. WATCH_PROVIDERS 제작사만 추림              │
 │  3. seen_models 에 없는 id = 신규             │◀──── D1
 └─────────────┬────────────────────────────────┘
               │ 신규가 있으면
               ▼
      텔레그램 Bot API ──▶ 📱 "🆕 새 모델 2개 ..."
               │
               ▼
      seen_models 에 기록 ──▶ 다음부터는 신규가 아님
```

**'오늘 출시(created)' 가 아니라 '본 적 없는 id' 로 판단합니다.**
크론을 한 번 놓치거나 모델이 소급 등록돼도 놓치지 않기 위해서입니다.
최초 실행은 알림 없이 현재 목록만 저장합니다 (수백 개 알림 폭탄 방지).

감시가 실패해도 `try/catch` 로 격리해 **알람 발송에는 영향이 없습니다.**

### 자주 헷갈리는 점

**"시간이 되면 텔레그램 봇이 깨어난다"가 아닙니다.**
봇은 실행되는 프로그램이 아니라 텔레그램 서버에 등록된 계정 이름일 뿐입니다.
모든 판단(시각 비교, 중복 체크)은 Worker가 하고, 텔레그램은 **메시지 배달만** 합니다.

**Worker는 평소에 떠 있지 않습니다.**
크론이 깨울 때(매 분)와 웹훅 요청이 올 때만 수십 밀리초 실행되고 사라집니다.
그래서 "서버를 계속 띄워둔다"는 개념 자체가 없고, 비용도 들지 않습니다.

## 비용

전부 무료 한도 안입니다.

| 항목 | 실제 사용량 | 무료 한도 | 사용률 |
|---|---|---|---|
| Worker 요청 | 1,440회/일 (매 분) | 100,000회/일 | 1.4% |
| D1 읽기 | 수천 row/일 | 500만 row/일 | ~0.1% |
| D1 쓰기 | 알람 수만큼 | 10만 row/일 | ~0% |
| Workers AI | 규칙이 실패한 문장만 | 무료 티어 제공 | 극소 |
| OpenRouter API | 24회/일 (매시 정각) | 인증 불필요 | — |

크론 주기를 1분으로 잡은 이유는, 알람이 하루 몇 번이든 **울릴 시각은 사용자가 정하기 때문에**
매 분 확인이 필요해서입니다. 어차피 한도의 1.4%라 정확도를 택했습니다.

## 사용법

### 말하듯 적으면 됩니다

텔레그램이든 웹 채팅이든 그냥 적으면 알람이 등록됩니다. `/add` 는 붙여도 되고 안 붙여도 됩니다.

```
내일 3시에 병원 알려줘
매일 아침 9시에 약 먹기
평일 8시 반 스탠드업 회의
다음주 월요일 오후 2시에 치과
이번주 금요일 저녁 7시에 회식
월수금 7시에 헬스장
25일 9시에 월세 이체
```

**시각 해석 규칙**

| 입력 | 해석 | 이유 |
|---|---|---|
| `3시` | 15:00 | 오전/오후를 안 밝힌 1~6시는 오후로 봅니다 |
| `03:00` | 03:00 | 24시간 표기는 명시로 간주해 그대로 |
| `새벽 3시` | 03:00 | 오전을 밝혔으므로 존중 |
| `9시` | 09:00 | 7~12시는 오전 |
| `8시 반` | 08:30 | `반` = 30분 |

**1회용과 반복은 날짜를 적었는지로 갈립니다.**

| 입력 | 결과 |
|---|---|
| `오후 3시에 병원` | 매일 15:00 **반복** (날짜를 안 적음) |
| `평일 오후 3시에 병원` | 평일만 반복 |
| `내일 오후 3시에 병원` | **1회** — 울리고 나면 자동 삭제 |
| `9/5 오후 3시에 병원` | 1회 |

주기(`매일`, `평일`, `주말`, `월수금`)와 날짜(`내일`, `다음주 월요일`)는 **시각보다 앞에**
적어야 합니다. 뒤에 붙이면 알림 내용으로 들어갑니다.

### 명령어

| 명령 | 설명 |
|---|---|
| `/list` | 등록된 알람 목록 |
| `/del 3` | 삭제 |
| `/off 3` / `/on 3` | 일시 중지 / 재개 |
| `/help` | 사용법 |
| `/check` | 새 AI 모델 지금 확인 (평소엔 매시 정각 자동) |
| `/id` | 내 chat_id 확인 |

### 웹 채팅 UI

`https://jarvis.choq.workers.dev` 에 접속해 비밀번호를 넣으면 채팅 화면이 뜹니다.
로그인은 30일 유지되고, 등록한 알람은 텔레그램으로 옵니다.

비밀번호 설정:

```bash
npx wrangler secret put WEB_PASSWORD
```

## 파일 구조

```
src/
  index.ts     진입점 — fetch(웹훅·웹UI) + scheduled(크론)
  watchers/
    openrouter.ts  OpenRouter 신규 모델 감시
  nlp.ts       자연어 해석 — 규칙 우선, 실패 시 Workers AI
  parse.ts     규칙 파서 (조사·꼬리말·요일 계산)
  cron.ts      크론 매칭, 타임존 변환, 한국어 설명 변환
  web.ts       웹 채팅 UI (HTML + 쿠키 인증)
  telegram.ts  Bot API 래퍼
scripts/
  cli.cjs      터미널용 알람 관리 (src/parse.ts 재사용)
  chatid.mjs   내 chat_id 조회
  webhook.mjs  웹훅 등록/조회/삭제
test/
  logic.test.ts  크론·파싱 로직 테스트 48개
```

**외부 의존성이 없습니다.** 크론 파서도 직접 구현했습니다.
자연어 해석은 Cloudflare 내장 Workers AI 바인딩만 씁니다 (API 키 불필요).

## 설계 노트

**중복 발송 방지** — 각 알람은 마지막으로 보낸 '분'을 `last_sent`에 기록합니다.
크론이 같은 분에 두 번 실행돼도 두 번 울리지 않습니다.

**놓친 알람 보정** — 크론이 몇 초 밀려 분을 건너뛸 수 있어, 매 실행마다
현재 분과 **직전 1분을 함께** 확인합니다. 중복은 `last_sent`가 막아줍니다.

**일회성 알람** — 예정 시각이 지났는데 아직 안 보냈으면 (놓쳤더라도) 즉시 발송합니다.
반복 알람과 달리 한 번은 반드시 도착하며, **보내고 나면 스스로 삭제**되어 목록에 쌓이지 않습니다.

**타임존** — Worker는 UTC로 돕니다. 저장된 타임존 기준 '벽시계 시각'으로 변환해
크론과 비교하며, `Intl.DateTimeFormat`에 `hourCycle: 'h23'`을 쓰는 이유는
자정이 24시로 나오는 문제를 피하기 위해서입니다.

**웹훅 보안** — `X-Telegram-Bot-Api-Secret-Token` 헤더를 검증합니다. URL을 알아내도
이 값이 없으면 403입니다. 여기에 `ALLOWED_CHAT_IDS`로 발신자까지 제한합니다.

**자연어는 규칙 우선, AI는 최후** — 규칙 파서가 흔한 표현을 0ms·무료로 처리하고,
실패한 문장만 Workers AI로 넘깁니다. 특히 **요일 계산은 AI에 맡기지 않습니다** —
날짜표를 줘도 일주일씩 틀리는 일이 잦아, 규칙에서 결정론적으로 계산합니다.

**AI 출력은 검증 후 사용** — 모델이 준 크론식·날짜는 형식을 정규식으로 확인하고,
과거 시각이면 거부합니다. 형식이 깨지면 규칙 파서의 안내 메시지로 되돌립니다.

**웹훅은 항상 200을 반환** — 텔레그램은 200이 아니면 같은 요청을 재시도합니다.
발송이 실패해도 명령은 이미 처리됐으므로, 200을 돌려 중복 실행을 막습니다.

## 트러블슈팅

**봇이 응답하지 않음** — 웹훅 상태를 확인하세요.

```bash
npm run webhook:info
```

`pending_update_count`가 쌓여 있으면 Worker가 요청을 못 받고 있다는 뜻입니다.
`last_error_message`는 과거 마지막 실패를 계속 표시하므로, 판단 기준은
`pending_update_count`입니다.

**배포 직후 SSL 에러** — 새로 만든 `*.workers.dev` 서브도메인은 인증서 발급에
수십 분에서 한 시간까지 걸릴 수 있습니다. 그동안에도 **알람 발송은 정상 동작**합니다
(아웃바운드는 인증서와 무관). 등록만 CLI로 하시면 됩니다.

**알람이 안 왔음** — DB에서 직접 확인합니다.

```bash
npx wrangler d1 execute jarvis-db --remote --command "SELECT * FROM reminders"
```

`last_sent`는 텔레그램 API가 성공했을 때만 기록되므로, 비어 있으면 발송 실패,
값이 있으면 전달 완료입니다.
